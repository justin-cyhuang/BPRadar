# 10 — ISO/IEC 20000-1:2018 benchmark detail

This spec is the authoritative seed-data reference for the `ISO/IEC 20000-1`
entry described generically in `01-frameworks.md`. It exists so the ISO
20000-1 catalog can be implemented and maintained without re-deriving
structure every time.

**Confidence note (read before seeding):** ISO/IEC 20000-1:2018's top-level
clause structure (4/5/6/7/9/10 below) follows the common "Annex SL"
high-level structure shared by ISO management-system standards (ISO 9001,
ISO 27001, ISO 20000-1, etc.) and is safely reliable. Clause **8
"Operation"** is where the standard defines the actual service management
processes (service portfolio, relationship & agreement, supply & demand,
service design/transition/delivery, resolution & fulfilment, service
assurance) — the exact official **subclause numbers** under clause 8 could
not be independently verified against the full paid standard text from
available tooling in this session. The control items listed under clause 8
in §3.5 use **descriptive codes (`OPS-xx`), not fabricated ISO subclause
numbers**, and are a curated representative checklist based on well-known
public ITSM/ISO 20000 process terminology. **Action required before final
seeding**: have someone with access to the actual ISO/IEC 20000-1:2018 text
confirm/replace the clause 8 subclause numbers, or keep the `OPS-xx` scheme
permanently if BPRadar prefers not to depend on exact official numbering.
This is called out again in §6.

## 4. Seeding shape (maps to `02-data-model.md`)

```
Framework: { Code: "ISO20000_1", Name: "ISO/IEC 20000-1", Version: "2018" }
Domain:    { FrameworkId, Code: "OPS", Name: "Operation", SortOrder: 5 }
Control:   { DomainId, Code: "OPS-07", Title: "Resolution and fulfilment — incident management",
             Description: "<paraphrase from §3.5>",
             GuidanceUrl: "https://www.iso.org/standard/70636.html" }
```
- `Framework.Version` = `"2018"` (current edition year).
- Domain `SortOrder` follows clause order: Context(1)/Leadership(2)/
  Planning(3)/Support(4)/Operation(5)/Performance evaluation(6)/
  Improvement(7).
- `GuidanceUrl` at the control level points to the ISO standard landing
  page, same rationale as `09-iso27001.md` §4 (no free official per-item
  pages exist for ISO standards).
- Seed data lives as a JSON/CSV fixture (see `../seed-data/frameworks/`),
  loaded by the same idempotent seeding routine, keyed on
  `FrameworkCode + ControlCode`.

## 5. Guidance for scoring, weighting, and dashboard use

- **Default weighting**: equal weight across all 32 items (1/32) for MVP,
  consistent with WAF/ISO 27001 approach.
- **Domain rollup**: clause score = average of its items' scores; note that
  `Operation` (`OPS`) carries more real-world assessment weight in practice
  even though it's one domain among seven equally-weighted ones here — flag
  this as a known MVP simplification, not a certification-accurate model.
- **Do not claim certification-audit equivalence**, same rationale as
  `09-iso27001.md` §5.
