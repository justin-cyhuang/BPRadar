# 09 — ISO/IEC 27001:2022 benchmark detail

This spec is the authoritative seed-data reference for the `ISO/IEC 27001:2022`
entry described generically in `01-frameworks.md`. It exists so the ISO 27001
catalog can be implemented and maintained without re-deriving structure every
time. Titles below are the standard's publicly well-known control names
(consistently reproduced across public ISO 27001:2022 transition/mapping
guides); descriptions are short, original paraphrases for mapping/seeding
purposes — they are **not** verbatim reproductions of the paid ISO/IEC
27001:2022 standard text, and BPRadar must never reproduce full clause
wording. Organizations needing authoritative wording must consult the
official ISO/IEC 27001:2022 Annex A document (iso.org, paid).

## 1. Source of truth

- **Standard**: ISO/IEC 27001:2022, Annex A (informative) — "Reference control
  objectives and controls", itself sourced from ISO/IEC 27002:2022.
- **Official landing page** (scope/purchase, not full text):
  https://www.iso.org/standard/27001
- **Structure verified against**: ISO's public scope page (confirms the
  standard defines an information security management system, ISMS) plus the
  widely-published post-2022-revision Annex A restructuring (93 controls,
  4 themes, replacing the 2013 edition's 14-clause/114-control layout). This
  restructuring is public knowledge broadly documented in vendor/compliance
  transition guides, not paywalled implementation text.
- Last verified against public structure summaries: 2026-08-03. Re-verify
  per §6 before any major re-seed, since implementation guidance (not the
  Annex A list itself) is periodically clarified by ISO/IEC 27002 updates.

## 2. Domain = Annex A theme mapping

| Domain (Theme) | Code prefix | Control count |
| --- | --- | --- |
| Organizational controls | `A.5` | 37 |
| People controls | `A.6` | 8 |
| Physical controls | `A.7` | 14 |
| Technological controls | `A.8` | 34 |

**Total: 93 controls.** `ControlCode` in BPRadar = the ISO code as-is
(e.g. `A.5.1`, `A.8.24`), so imported CSV/XLSX rows using the official codes
align automatically (see `04-import.md` alignment rules).

## 4. Seeding shape (maps to `02-data-model.md`)

```
Framework: { Code: "ISO27001_2022", Name: "ISO/IEC 27001", Version: "2022" }
Domain:    { FrameworkId, Code: "A.5", Name: "Organizational controls", SortOrder: 1 }
Control:   { DomainId, Code: "A.5.1", Title: "Policies for information security",
             Description: "<paraphrase from §3.1>",
             GuidanceUrl: "https://www.iso.org/standard/27001" }
```
- `Framework.Version` = `"2022"` (the current Annex A structure). If ISO
  publishes a future revision that changes control counts/codes, bump this
  and re-run §6.
- Domain `SortOrder` follows Annex A theme order: Organizational, People,
  Physical, Technological.
- `GuidanceUrl` at the control level points to the general standard landing
  page (iso.org) since ISO does not publish free per-control pages the way
  Microsoft Learn does for WAF; do not link to pirated/paywalled full-text
  mirrors.
- Seed data lives as a JSON/CSV fixture (see `../seed-data/frameworks/`),
  loaded by the same idempotent seeding routine used for WAF, keyed on
  `FrameworkCode + ControlCode`.

## 5. Guidance for scoring, weighting, and dashboard use

- **Default weighting**: treat all 93 controls as equal weight (1/93) for
  MVP, consistent with the WAF approach in `08-waf.md` §5. Do not invent a
  certification-body-endorsed weighting scheme.
- **Domain rollup**: theme score = average of its controls' scores (e.g.
  Organizational = average of A.5.1–A.5.37).
- **Do not claim formal certification-audit equivalence** — a passing
  BPRadar self-assessment is not the same as passing an accredited ISO
  27001 certification audit; this is a readiness/gap-tracking tool. Call
  this out in `05-dashboard.md` copy if not already clear.
- **Applicability note**: unlike WAF (all controls generally apply to any
  Azure workload), real ISO 27001 implementations use a **Statement of
  Applicability (SoA)** to mark some Annex A controls as not applicable to
  a given organization. BPRadar already supports this per-control via
  `ComplianceStatus.NotApplicable` — no schema change needed, but dashboard
  copy should note that `NotApplicable` here often reflects a formal SoA
  exclusion decision, not just "not yet assessed".

## 6. Keeping this spec current

1. Before a major re-seed, check ISO's public standard page
   (`https://www.iso.org/standard/27001`) and reputable transition-guide
   summaries for any revision announcement affecting Annex A structure.
2. If a revision changes control counts/codes, update this file's §2/§3
   first, then the seed fixture, then bump `Framework.Version`.
3. Never copy full clause/control requirement text verbatim — keep
   paraphrasing to one line; direct users to the official ISO/IEC 27001
   purchase page for authoritative wording.
